# Native relay phase receipts and P2P hints

The eight-player Firefox witness could lose a baseline or a later frame read
after corrected history. A separate mixed-browser run reported native expiry
during FIFO release. Its sender had finished draining, but the artifact held
only whole-room SDK queue peaks at the reporters. The same session investigated
why a SignalFish pin update disabled every P2P schedule hint.

| Finding | Evidence | Action |
| --- | --- | --- |
| A page rejection can discard another page's timely receipt. | The scripted browser entrypoint initially lost the delayed sibling's baseline and omitted the deadline when a separate page hung. The revised control retains both available observations and both failure causes. | Keep per-page dispatch and receipt within the shared deadline. Retire unfinished reads before diagnostic collection. |
| A release and expiry can share a controller clock value. | The equal-time control initially assigned a 33-packet completion that arrived after expiry instead of the earlier 16-packet progress sample. | Capture backlog and accepted traffic before cleanup. Join the frozen peer's sampled release position by controller receipt order. |

The 13 lifecycle schedules also matched between both runs. | Fingerprint the P2P generator, Fortress source and locked Rust build. Keep full live prefix verification. |
