## Findings

| Finding | Evidence | Action |
| --- | --- | --- |
| One job, not the tests, set CI wall time. | 4.7.2 WebRTC ran eight labels in one 10m13s step; other jobs ended by 8m21s. | Split the labels into two balanced jobs: 12m20s → 7m49s. |
| Alphabetical shard order put the slowest suite last. | `test_webrtc_mesh_backlog.gd` sorted last and set the local tail. | Recorded times order shards; slow suites split by case. |
| A time-based split can feed itself. | Review: a split suite recorded the sum of per-case startups and stayed split. | Recorded times subtract extra startups; a suite that is no longer slow runs whole. |
| More jobs only help when they shorten the slowest one. | Separate relay and integration jobs added about two setup minutes each and no wall time. | Folded back; split only the job that sets the pace. |
| Agents sharing one machine distort timings and trip watchdogs. | Load 37 on 16 CPUs; three agents saw 30s watchdog failures in untouched suites. | Benchmark only on an idle machine, old and new back to back. |
| A delegated probe change skipped its own receipt controls. | `make test-reference` failed in CI after the #45 change to `ownership_probes.py`. | Fixed. Any change under `scripts/reference/` runs `make test-reference` before commit. |
| A cache hit is not a faster step. | The dependency cache restored, yet the build still took 67s (fresh cargo home per run). | Deleted; check step time, not cache logs. |
