# Devcontainer & Container Tooling Facts

Operational facts learned while building this repo's devcontainer
(`.devcontainer/`); feeding retrospective
[2026-10-09-devcontainer-bootstrap](../retrospectives/2026-10-09-devcontainer-bootstrap.md).

| Fact (one assertable sentence) | Evidence (command + output, file:line, or measurement) | Verified |
| --- | --- | --- |
| The `mcr.microsoft.com/devcontainers/base:ubuntu-24.04` image ships no python3, and devcontainer features install only `python3-minimal` (no stdlib: `json`, `unittest`, `dataclasses`), so repos needing stdlib Python must apt-install the full `python3` package in their Dockerfile before features run. | `/var/log/apt/history.log` in container: `apt-get -y install --no-install-recommends python3-minimal`; `python3 -c "import dataclasses"` → `ModuleNotFoundError` before fix, pass after. | 2026-10-09 |
| Devcontainer features execute in layers AFTER the Dockerfile build, so a feature-installed runtime (e.g. Node via the node feature) is invisible to Dockerfile `RUN` layers; runtimes needed at build time must be installed in the Dockerfile itself. | Build failure: `npm: not found` semantics — godot-mcp layer needed npm; fixed by installing Node in Dockerfile before features (`.devcontainer/Dockerfile`). | 2026-10-09 |
| `postCreateCommand` runs only on container CREATE; `devcontainer up` reuses an existing container after image/config changes unless `--remove-existing-container` is passed, so post-create changes can silently not run. | `devcontainer-build4.log` (failed run) and `devcontainer-build5.log` (success) report the identical `containerId`. | 2026-10-09 |
| Docker creates missing named-volume mount-point parent directories as root, making the mounted volume unwritable for the remote user; pre-create the mount points in the image and `chown` them so first-mount copy preserves ownership. | post-create failure: `/home/vscode/.cache/uv/CACHEDIR.TAG: Permission denied (os error 13)`; fixed by `mkdir -p` + `chown -R vscode:vscode` in image. | 2026-10-09 |
| `npx -y <pkg>` does NOT resolve a globally installed package — it fetches from the npm registry even when the package is already on PATH via `npm i -g`. | Reviewer empirical test with registry pointed at a dead endpoint: `npx -y @coding-solo/godot-mcp` → `FetchError ... ECONNREFUSED` despite global install. | 2026-10-09 |
| Claude Code reads credential-like environment variable names as EMPTY (with no warning) when expanding `${VAR}` in remote MCP servers' `url`/`headers`, so headers must use a custom non-credential name; stdio `env` blocks are unaffected. | code.claude.com/docs/en/mcp § "Credential variables that read as empty" ("If you write `Bearer ${ANTHROPIC_AUTH_TOKEN}`, the server receives `Bearer`... A name outside this set, such as `API_KEY`, expands as written"). | 2026-10-09 |
| GitHub `releases/latest/download/<asset>` is a download redirect that avoids the REST API quota; install scripts that query `api.github.com/repos/.../releases/latest` unauthenticated fail under the 60 req/h IP limit during container builds. | opencode installer failure `Failed to fetch version information` in build; direct asset download succeeds. | 2026-10-09 |
| Docker `--env-file` keeps quotes verbatim and treats trailing text as part of the value; `GITHUB_TOKEN="x"` and `KEY=x # comment` both corrupt the value silently. | Docker CLI documented env-file semantics; corruption modes added to `.devcontainer/devcontainer.env.example`. | 2026-10-09 |
| BuildKit rejects ARG expansion in `COPY --from` ("variable expansion is not supported for --from"); the workaround is a dedicated `FROM ... AS x` stage, and predefined args (e.g. `TARGETARCH`) must still be re-declared inside a stage to be visible in `RUN`. | Build error in first `up`; fixed via `FROM ghcr.io/astral-sh/uv:${UV_VERSION} AS uv-bin` stage. | 2026-10-09 |
| For fail-closed firewall setup, DROP policies must be the immediate successors of the filter-table flush: every fallible statement (chain deletes, NAT replay, network fetches) belongs either before the flush (gather phase) or guarded behind the policies. | Adversarial review rounds 2-4 each found a residual flush→policy window (mangle flush, xargs NAT replay, `iptables -X`); final ordering verified in `.devcontainer/init-firewall.sh`. | 2026-10-09 |
| OpenCode 2.0.26 initializes its runtime MCP catalog asynchronously, so a successful `debug config` followed immediately by `mcp list` can still report no servers in a fresh daemon. | PR #54 first fresh image runs: all three discovery checks failed on both architectures; isolated fresh-service reproduction: first list empty, second list names pending; `.devcontainer/verify-tools.sh` now polls within a fixed deadline. | 2026-10-10 |
| Devcontainers CLI 0.89.0 uses `--build-no-cache`, not `--no-cache`, to rebuild image layers without cache. | `npx @devcontainers/cli@0.89.0 up --help`; corrected `.devcontainer/README.md` command and maintenance table. | 2026-10-10 |
